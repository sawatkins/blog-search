# Production crawler pilot — 2026-09-07

## Scope and result

The approved pilot processed exactly 20 jobs: two feeds and 18 posts, using two
workers. All 18 posts were new. The database and Elasticsearch both increased
from 314,149 to 314,167 pages. Title, URL, publication date, and full extracted text
matched for all 18 documents. A post from each blog was also found through the
running application's `/api/search` endpoint (HTTP 200).

Feeds used:

- `https://jvns.ca/atom.xml`
- `https://simonwillison.net/atom/everything/`

Both appear in the current Small Web list, which contained 40,627 valid feed URLs
when checked. Only these two feeds were imported; the full list was not queued.

The pilot finished at 02:21:58 UTC with no crawl errors, skipped jobs, active
leases, or pending index writes. It left 37 immediately due jobs queued but not
running: 32 posts, three sitemaps, and two archives. Completed feed/page jobs stay
`pending` with future due dates, so `pending` alone is not an unfinished-work count.

## Compatibility fix

The first worker attempt stopped before claiming work because the real `domains`
table predated the schema in the repository: it had `last_feed_check`, but no
`next_allowed_scrape`. `CREATE TABLE IF NOT EXISTS` did not upgrade that table.

The explicit migration now adds the missing column idempotently and preserves
legacy fields. Migration lock waits are limited to five seconds. A new regression
test verifies the legacy upgrade, preserved feed history, and working rate-limit
cooldowns. All 141 tests passed against disposable PostgreSQL 17. The actual
pre-pilot schema and scoped blog backup were also restored locally; migration
and an empty-queue claim then succeeded, with all 137 restored posts preserved.

## Safety and remaining work

The pre-pilot schema and 137 existing posts from the two blogs are backed up in
`/home/debian/blog-search/backup/crawler-pilot.OrKnhE/` (ignored by Git). This is a
scoped pilot backup, not a complete database backup. No preexisting posts were
changed. Before this pilot, the last stored scrape timestamp was 2025-08-26.

The live web service remained active and was not restarted. Its newly refactored
Python code has therefore not been deployed into the running process yet. No
crawler timers were installed or enabled, no full reindex was run, and the old
SQS queue was untouched. The disposable test database was removed after testing;
the backup files remain on this server.

This pilot validates new-post ingestion and indexing, not broad feed compatibility,
historical discovery, or overnight scheduling. Next, run a bounded, varied-blog
pilot that actually reaches archive/sitemap work before enabling daily updates.
